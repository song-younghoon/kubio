Kubio kubio.json v0.22 Specification
Status: Agreed specification
Base: v0.21


1. Scope

v0.22 adds a route-level prefix URI rewrite. It changes the upstream request
path after route selection and before proxying, while preserving the existing
query string. It does not add regex rewrites, query rewrites, redirects, fixed
responses, or response bodies.


2. Configuration

A route may set `rewrite` to a path pattern:

    {
      "sites": [{
        "hosts": ["example.com"],
        "target": "http://localhost:3000",
        "routes": [{
          "path": "/api/*",
          "rewrite": "/v1/*"
        }]
      }]
    }

The value is a decoded origin path beginning with `/`, without query,
fragment, control characters, or an empty value. Percent escapes in the
configuration have no special meaning and are treated as literal path bytes.
It may contain no `*`, or only one trailing `/*`, using the same wildcard
grammar as route paths. A rewrite with `/*` replaces its prefix and appends
the source route's matched suffix. A rewrite without `/*` replaces the
complete path with that exact path. The source route may be exact or
wildcard.

For an exact source route, the suffix is empty. For a wildcard source `P/*`,
the suffix is the exact decoded substring after `P`: it is empty when the
incoming path is `P`, `/` when the incoming path is `P/`, and the remaining
substring otherwise. For the root source `/*`, `P` is empty and the suffix is
the complete decoded incoming path. A destination `Q/*` is formed by
concatenating `Q` and the suffix without slash normalization; if that result
is empty, it becomes `/`. Therefore `/api/*` rewrites `/api` to `/v1`,
`/api/` to `/v1/`, and `/api/users` to `/v1/users` when the destination is
`/v1/*`.

`rewrite` is valid only on routes. Existing strict parsing rejects unknown
keys, aliases, exact duplicate object keys, nulls, non-strings, and empty
strings; no alternative spelling is accepted. Invalid path syntax and
site/backend placement are configuration errors. `rewrite` is rejected only
when `strip` is `true`; an explicit `strip:false` is allowed and has no
interaction with `rewrite`. Existing route matching is unchanged and is
evaluated against the incoming path before rewriting.


3. Rewrite behavior

The rewrite is applied only after the winning route has been selected. The
upstream target host, scheme, headers, and method are unchanged. Kubio changes
only `ProxyRequest.Out.URL.Path` and `Out.URL.RawPath`; it never mutates
`ProxyRequest.In`, the selected route, or the client request used for access
logging.

Kubio copies `Out.URL.RawQuery` from the incoming `RawQuery` and copies
`Out.URL.ForceQuery` from the incoming `ForceQuery` unchanged. It does not
parse, normalize, clean, join, or re-encode the query; an empty query with
`ForceQuery:true` remains a trailing `?`.

For a source `/api/*` and rewrite `/v1/*`, `/api/users` becomes `/v1/users`.
For a source `/health` and rewrite `/status`, the upstream path is `/status`.
The root wildcard `/*` has an empty source prefix and therefore rewrites the
complete incoming path to the rewrite prefix plus its suffix.

Kubio updates `URL.Path` and preserves a valid corresponding `RawPath` when
the incoming path was escaped. A non-empty incoming `RawPath` is valid only
when it uses valid Go URL path escaping and
`url.PathUnescape(RawPath) == Path`. For a valid value and a wildcard source,
Kubio scans the raw bytes left to right, decoding bytes until exactly the
decoded source prefix `P` has been consumed; the remaining raw bytes are the
suffix. `P` is empty for `/*`, so the raw suffix is the complete incoming
`RawPath`. For an exact source route, the scan is skipped and the raw suffix is
empty.

For an exact destination, Kubio uses the URL-escaped destination path. For a
wildcard destination, it concatenates the URL-escaped decoded destination
prefix and the retained raw suffix without slash normalization. Kubio keeps a
candidate only when it is valid and decodes exactly to the resulting `Path`;
otherwise it clears `RawPath`. If the incoming `RawPath` is empty, the
rewritten `RawPath` remains empty. Host selection, route matching, and
access-log path fields retain the original client path.


4. Reload and failure behavior

Kubio validates and compiles rewrite patterns while constructing a generation.
Invalid configuration terminates startup and, on reload, is logged while the
current generation continues serving unchanged. Valid reloads publish
atomically without downtime; in-flight requests retain their generation's
rewrite behavior.


5. Performance constraints

Rewrite patterns are parsed once per generation. The request path performs
only the selected route's precompiled prefix operation; routes without
`rewrite` retain the existing path. No regex engine, global lock, or config
read is added to the request path.


6. Deferred scope

The following remain unresolved and move to v0.23:

- Fixed route responses, redirects, and custom error bodies.
- Metrics, configurable log sinks/formats, and health/admin/reload endpoints.
- Forwarded and PROXY protocols.
- Client certificates, mutual TLS, TLS passthrough, configurable TLS policy,
  ACME, multiple listener certificates, and listener SNI certificate
  selection.
- Rate limiting, authentication, compression, caching, service discovery,
  response trailers, conditional response headers, request-header policies,
  adaptive retry policies, and policies for Kubio-generated or intermediate
  responses.
