Kubio kubio.json v0.4 Proposal
Status: Deferred features; discussion not started
Base: v0.3


1. Purpose

This proposal carries every feature from the original v0.3 proposal that was
not selected for v0.3. It defines no agreed behavior yet. Its scope must be
narrowed and selected items must be specified before promotion.


2. Backend resilience and upstream transport

- Retry and failover rules.
- Active or passive health checks.
- Weighted target selection.
- Per-backend connection and response-header timeouts.
- HTTPS upstream CA and SNI settings.

Future work must define retry safety, health state, selection priority,
timeout inheritance, transport ownership, and reload behavior for whichever
items are selected.


3. Additional route matching

- Request header conditions.
- Query parameter conditions.
- Client IP conditions.

Future work must define condition syntax, validation, precedence, and
interaction with v0.3 method matching.


4. Response headers

- Response header set.
- Response header removal.
- Multiple response header values.
- Explicit set, add, and remove operation ordering.


5. Client-facing TLS

- Manual certificates.
- Certificate selection by host.
- HTTP-to-HTTPS redirects.
- Automatic ACME certificates.


6. Observability and administration

- Structured access logs.
- Request and upstream metrics.
- Health and metrics endpoints.
- Reload status reporting.


7. Additional proxy protocols and routing actions

- RFC Forwarded headers.
- PROXY protocol.
- URI rewriting.
- Redirect responses.
- Fixed responses.
- Custom error bodies.


8. Application gateway features

These remain candidates only when backed by a concrete use case:

- Rate limiting.
- Authentication.
- Response compression.
- Response caching.
- Service discovery.
