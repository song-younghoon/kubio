Kubio kubio.json v0.5 Proposal
Status: Deferred features; discussion not started
Base: v0.4


1. Purpose

This proposal carries every candidate from the original v0.4 proposal that was
not selected for v0.4. It defines no agreed behavior yet. Its scope must be
narrowed before promotion.


2. Backend resilience and upstream transport

- Retry and failover rules.
- Active or passive health checks.
- Weighted target selection.
- Per-backend connection and response-header timeouts.
- HTTPS upstream CA and SNI settings.


3. Additional route matching

- Request header conditions.
- Query parameter conditions.
- Client IP conditions.


4. Response header extensions

- Response header removal.
- Multiple configured values for one response header.
- Additive response header values that preserve existing values.
- Explicit ordering among set, add, and remove operations and between site and
  route operations.


5. Client-facing TLS

- Manual certificates.
- Certificate selection by host.
- HTTP-to-HTTPS redirects.
- Automatic ACME certificates.


6. Observability and administration

- Structured access logs.
- Request and upstream metrics.
- Health and metrics endpoints.
- Reload status reporting.


7. Additional proxy protocols and routing actions

- RFC Forwarded headers.
- PROXY protocol.
- URI rewriting.
- Redirect responses.
- Fixed responses.
- Custom error bodies.


8. Application gateway features

These remain candidates only when backed by a concrete use case:

- Rate limiting.
- Authentication.
- Response compression.
- Response caching.
- Service discovery.
