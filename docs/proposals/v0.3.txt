Kubio kubio.json v0.3 Proposal
Status: Deferred features; discussion not started
Base: v0.2


1. Purpose

This file carries forward features excluded from v0.2. It is not a
specification yet. The scope must be narrowed and each selected item must be
fully defined before v0.3 is finalized.


2. Backend resilience and upstream transport

Consider extending v0.2 backends with:

- Retry and failover rules.
- Active or passive health checks.
- Weighted target selection.
- Per-backend connection and response-header timeouts.
- HTTPS upstream CA and SNI settings.

Retry safety, health state, selection priority, timeout inheritance, and reload
behavior must be defined before implementation.


3. Additional route matching

Consider route conditions beyond host and path:

- HTTP method.
- Request header.
- Query parameter.
- Client IP.

The matching precedence and interaction between conditions must be defined
before implementation.


4. Response headers

Consider extending headers beyond v0.1 request injection:

- Response header set.
- Header removal.
- Multiple header values.
- Explicit set, add, and remove operation ordering.


5. Client-facing TLS

Consider TLS termination on Kubio's public listener:

- Manual certificates.
- Certificate selection by host.
- HTTP-to-HTTPS redirects.
- Automatic ACME certificates.


6. Observability and administration

Consider:

- Structured access logs.
- Request and upstream metrics.
- Health and metrics endpoints.
- Reload status reporting.


7. Additional proxy protocols and routing actions

Consider:

- RFC Forwarded headers.
- PROXY protocol.
- URI rewriting.
- Redirect responses.
- Fixed responses.
- Custom error bodies.


8. Application gateway features

Consider only when there is a concrete use case:

- Rate limiting.
- Authentication.
- Response compression.
- Response caching.
- Service discovery.
